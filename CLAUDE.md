# Контекст проекта

Квест-борд медиа-отдела студенческой внеучебки. Руководство ставит задачи,
отдел разбирает их как квесты в Telegram, куратор принимает работу.

Планы и статус фаз — в [ROADMAP.md](ROADMAP.md), развёртывание — в [DEPLOY.md](DEPLOY.md).

## Стек

- **Next.js 15 (App Router) + React 19 + Tailwind 4** — админка
- **grammY** — бот, отдельный процесс, long polling в деве
- **Prisma + PostgreSQL** — одна база на обе поверхности
- Postgres в docker-compose на порту **5433** (на 5432 на этой машине живёт другой Postgres)

## Команды

```bash
npm run db:up      # поднять Postgres
npm run db:migrate # миграция схемы
npm run db:seed    # суперадмины из BOOTSTRAP_ADMIN_IDS
npm run dev:all    # админка + бот вместе
npm run typecheck
npm test           # интеграционные тесты на настоящей базе, за собой убирают
```

## Где что

- `src/server/tasks.ts` — все переходы статусов квеста. Бот и админка зовут только его.
- `src/server/cards.ts` — текст и кнопки карточки квеста, синхронизация карточки в чате.
- `src/server/login.ts` / `session.ts` — вход: первый без `next/*` (его импортирует бот),
  второй с cookies (только админка). Не смешивать — бот живёт вне Next.js.
  Входов два: кнопка «Войти через Telegram» (`/auth/telegram`, проверка подписи виджета)
  и запасная ссылка из бота (`/admin` → `/auth/[code]`).
- `src/lib/labels.ts` — только `import type` из Prisma: файл попадает в клиентский бандл.
- `src/server/miniapp-auth.ts` / `miniapp.ts` — вход и действия Mini App.
- `src/components/miniapp/` — экраны приложения; `src/lib/telegram-webapp.ts` — обёртка над `window.Telegram.WebApp`.

## Инварианты — не ломать

1. **Переходы статусов только атомарные.** Никогда не читать статус и потом писать
   отдельным запросом: двое нажмут «Беру» одновременно и оба получат задачу.
   Только `updateMany` с ожидаемым статусом в `where`, проверка `count`:

   ```ts
   const { count } = await prisma.task.updateMany({
     where: { id, status: "OPEN", assigneeId: null },
     data: { status: "CLAIMED", assigneeId: userId, claimedAt: new Date() },
   });
   if (count === 0) return "уже разобрали";
   ```

   Так же устроены приёмка (очки не начисляются дважды) и обмен кода входа.

2. **EXPIRED не значит «удалено».** Если квест никто не взял до `claimBy`,
   работа всё равно нужна. Статус меняется, куратор получает уведомление,
   задача остаётся видимой. Тихо терять работу нельзя — на этом умирает доверие
   ко всей системе.

3. **`Task.eventId` — nullable, и это осознанно.** Половина работы отдела
   (посты, мемы, рубрики) не висит ни на каком мероприятии. Не делать событие
   обязательным и не заводить фиктивные «события-заглушки».

4. **Навыки — множественные.** `Task.skills` и `User.skills` — массивы.
   Подсветка «подходят тебе» срабатывает по **любому** пересечению, а пустой
   `Task.skills` значит «квест для всех», а не «ни для кого». Свои навыки
   человек отмечает сам в Mini App, на вкладке «Я».

5. **Два дедлайна различаются.** `claimBy` — до когда взять, `dueAt` — до когда
   сдать. Не схлопывать в один.

6. **Каждая смена статуса пишется в `TaskEvent`.** Это источник правды для
   аналитики и для разбора спорных ситуаций.

7. **Три входа — три разные схемы подписи, не путать.**

   | Вход | Ключ HMAC | Файл |
   |---|---|---|
   | Mini App (`initData`) | `HMAC_SHA256("WebAppData", токен)` | `miniapp-auth.ts` |
   | Кнопка «Войти через Telegram» | `SHA256(токен)` | `login.ts` |
   | Ссылка из бота (`/admin`) | случайный код, хэш в базе | `login.ts` |

   В строке проверки `initData` исключается **только** `hash`; поле `signature`
   в неё входит (оно для сторонней Ed25519-проверки, там правила другие).
   На каждое правило есть тест — `miniapp-auth.test.ts`, `login.test.ts`.

8. **Любой вход одноразовый.** Код из бота тратится только POST-ом: `/auth/[code]`
   на GET лишь показывает «Войти как …», иначе ссылку «съест» превью Telegram.
   Подписанный пакет виджета валиден сутки и лежит в URL, поэтому его `hash`
   записывается в `LoginCode`: повторно тот же пакет не пустит.

9. **Сбой Telegram не откатывает действие в базе** — кроме публикации: квест, чья
   карточка не ушла в чат, возвращается в черновик. Остальное логируется.

## Грабли

- **env на клиенте.** `src/lib/env.ts` читает `process.env` и бросает в браузере.
  Любой импорт из клиентского компонента — даже через цепочку (`board.tsx` →
  `task-card.tsx` → `time.ts` → `env.ts`) — роняет страницу целиком. Типы это не
  ловят, только запуск. Клиентским компонентам пояс передаётся **пропом**,
  а помощники берутся из `lib/tz-input.ts` и `lib/relative.ts`, которые env не знают.
  (`server-only` тут не годится: бот и тесты идут обычным node, и пакет бросает и у них.)
- **Время.** `datetime-local` приходит без пояса — это часы отдела (`APP_TZ`),
  не UTC и не пояс сервера. На сервере — `parseLocalInput` из `src/lib/time.ts`,
  на клиенте — та же функция из `lib/tz-input.ts` с явным поясом.
- **Mini App.** Тему, высоту вьюпорта и безопасные зоны задаёт Telegram своими
  CSS-переменными — своих цветов и `100vh` не использовать. Скрипт
  `telegram-web-app.js` правит `<html>` до гидратации, поэтому на нём
  `suppressHydrationWarning`.
- **Формы.** `<form action={...}>` в React 19 сбрасывает поля после экшена — даже
  при ошибке валидации. Формы с вводом — через `ActionForm`, он отправляет вручную.
- **Telegram и localhost.** URL-кнопки на `http://localhost` Telegram отклоняет —
  см. `appUrlIsPublic` в `src/lib/env.ts`. Виджет входа работает только на домене из
  `/setdomain` у @BotFather, на localhost показывает «Bot domain invalid».
- **Скрипт виджета** вставлять через `useEffect`, не тегом `<script>` в JSX: React 19
  при SSR уносит async-скрипты в `<head>`, а виджет рисует кнопку на месте своего тега.
- **Windows.** Запущенные бот и `next dev` держат DLL движка Prisma: перед
  миграцией их остановить. Имя compose-проекта задано явно — кириллица в имени
  папки схлопывается в пустое имя.

## Соглашения

- Интерфейс и тексты бота — по-русски, на «ты».
- Комментарии в коде — по-русски, только там, где объясняют *почему*, а не *что*.
- `BigInt` для `telegramId` и `chatId` — id чатов не влезают в `Int`.
- Ветка на фазу: `phase-N-<короткое-имя>`.
